# VelocityX

**VelocityX** is an experimental fork of the Velocity proxy engine, created to prove the concept of "promptless" (zero-prompt) development using Artificial Intelligence.

## Why VelocityX?

The main technical goal of VelocityX is to provide server administrators with an **all-in-one** solution, eliminating the need to install and configure additional third-party plugins.

* **Velocity Base:** A modern, fast, and secure proxy engine featuring excellent thread distribution.
* **Velocity-CTD Features:** Built-in popular optimizations (fixing memory leaks upon player disconnection, queue optimization) and native global commands like `/hub` and `/alert`.
* **Built-in AntiBot:** Trash traffic filtering and packet-based bot DoS protection directly at the core network level, without heavy external plugins.

## Inside the Project: Pure "AI Slop"

This project is pure, unadulterated **AI slop**, and we make no secret of it. 

**Not a single line of code was written manually**, nor were complex, multi-page prompts used to create VelocityX. The entire development process looked like this:

1. **Concept:** A human formulated a general idea from scratch.
2. **Sources:** Collected links to the source materials (upstream Velocity and Velocity-CTD commits).
3. **Execution:** The AI "glued" these components together into a single entity based on a simple text request.

The AI did not concern itself with perfect Java code architecture. Its main task was to bypass dependency conflicts in Gradle and deliver a compilable, working `.jar` file. Inside, the code may look messy, but it perfectly reflects the concept of **"disposable software tailored for a specific task"**.

## Project Goal

The goal of VelocityX is not to compete with major market players, but to serve as a **social engineering experiment**.

The project clearly demonstrates that today, the entry barrier to server software development has been completely demolished. To create a custom network core, you no longer need years of experience in asynchronous programming (Netty) and Gradle. All it takes is a clear vision of the product and the ability to explain it to an AI in plain words.

## Disclaimer and Risks

> [!WARNING]
> Since the code is entirely generated by an AI, using VelocityX on large commercial projects with high player counts carries significant risks.

* **Unpredictability:** The AI could have made logical errors that will only surface under high load (e.g., thread deadlocks or race conditions).
* **Security:** During the automatic code merging process, internal packet security checks might have been accidentally disabled or altered.
* **Support:** The project is provided **"as is"**. Fixing critical bugs by the author is highly difficult, as the entire compilation and merging logic was handled by the AI.

*Use this project at your own risk. It is intended primarily for educational purposes, testing AI technologies, or running home servers.*
